# 事件包系统改造 · 实施计划

> 状态：待用户确认
> 计划 ID：event-package-routing
> 目标：解决魔禁卡各剧情篇章“过度偏离、无理由跳章、模型脑补过多”问题。
> 计划范围：在现有 MVU + 世界书 + Tavern Helper 架构内完成，不引入数据库。

## 1. 目标、红线与完成定义

### 1.1 目标

将当前时间线中列出的所有重要原著篇章和既有重要支线，统一改造成独立的、可路由的事件包；让玩家可以在事件包内自由改写剧情，但当前篇章未完成或未明确退出前，AI 不得无理由跳到其他篇章。

### 1.2 红线

- 不新增数据库、外部存储或独立剧情服务。
- 不新增风险值、失败收场、死亡、解密、异常事件或反噬机制。
- 不把玩家自由偏离改成强制复刻原著。
- 不允许模型仅凭“偏离等级”数字决定换篇；后续剧情必须依据具体偏离事实和世界线后果。
- 不改变已验证的 4 折叠面板、变量写回闭环、开局页面和脚本 CDN 架构，除非验收证明必须改变。
- 不直接修改发布 PNG；所有修改先落在 `src/` 源文件，再按项目发布链重建。
- 不改动 `src/神秘复苏模拟器/`。
- 不把当前事件做成逐轮完整日志；MVU 只保存当前状态和必要的因果事实。
- 原著资料只作事实锚点，剧情文字必须原创重写，不复制参考卡文案。

### 1.3 完成定义

本计划完成必须同时满足：

1. 当前 `原著剧情锚点总览.txt` 中列出的所有重要篇章均有独立事件包。
2. 每个事件包包含稳定 ID、核心事实、节点表、分支规则、换篇条件和防剧透边界。
3. 当前主线能通过“阶段 + 锚点 + 节点”被模型和变量层明确定位。
4. 玩家在篇章内改写时保留当前篇章身份，并记录具体偏离事实。
5. 玩家未明确退出、跳过、时间跳跃或完成事件时，不自动换篇。
6. 详细事件包不再全部作为蓝灯常驻条目注入；路由方案经过真实运行时验证。
7. 旧事件文本中的反噬、代价、失败收场等冲突口径清理完毕。
8. 源码、世界书引用、构建产物、PNG 载荷和真实 SillyTavern 行为全部通过对应验收门。

## 2. 现状与根因

1. 幻想御手篇目前只在原著锚点总览中占 1 行，没有独立事件文件。
2. 原著锚点总览中的其他篇章也多为 1-4 行概览，无法提供可执行的剧情顺序。
3. 现有 8 个剧情事件文件全部使用蓝灯常驻，模型可能同时看到多个不相邻篇章。
4. 现有 `主线进度` 没有“当前节点”字段，只有阶段、锚点、已完成/可触发节点等较宽泛状态。
5. 变量规则允许玩家偏离原著，但没有规定“偏离仍留在当前篇章”和“何时才允许换篇”。
6. 当前事件文件仍有与最终设计冲突的旧措辞：不致死、失败受挫、搞笑反噬、能力代价和跨体系代价。
7. `schema.ts` 已是最终无风险版本，但事件文件与变量规则尚未完全同步。

## 4. 统一事件包契约

每个 `.txt` 事件包采用同一结构，事件内容是模型可见规则，不写开发过程说明：

```text
【事件包：名称】
事件包ID：FANTASY-HAND
所属阶段：阶段0·旧约·前日谭
时间窗口：5月-6月
别名与触发词：...

== 1. 核心定位 ==
主题、事件起因、原著锚点、玩家可进入的位置

== 2. 不可丢失的核心事实 ==
时间、核心人物、世界观事实、事件因果

== 3. 玩家可改写的部分 ==
介入时机、帮助对象、行动方法、人物关系、事件结果

== 4. 节点推进表 ==
节点ID / 进入条件 / 场景目标 / 可见角色 / 玩家行动 / 结果 / 下一节点

== 5. 分支和偏离规则 ==
篇章内偏离、核心结果改写、延后、跳过、原创收束

== 6. 换篇条件 ==
完成、明确退出、明确跳过、明确时间跳跃、明确选择新锚点

== 7. 防剧透边界 ==
本篇允许揭露、暂不揭露、不可提前调用的后期事实

== 8. 状态写回契约 ==
主线进度、任务追踪、NPC关系、势力关系、物品、世界线记录的更新要求

== 9. 收束结果 ==
多个合法结局，不使用死亡/失败收场/风险/反噬
```

### 4.1 节点约束

- 每个原著事件包至少 6 个、最多 10 个主要节点；具体数量按事件复杂度决定。
- 节点 ID 稳定、唯一、不可随意改名；格式为 `{PACKAGE_ID}-{NN}`，例如 `FH-01`。
- 每轮最多推进一个主要节点。
- 节点推进必须由玩家行动、时间流逝、事件结果或势力介入支持。
- 不能因为模型想加速而连续跳过多个节点。
- 节点表不是一本道，至少明确一条原著近似路线和一条玩家改写路线。

## 5. 主线状态契约

### 5.1 推荐变量结构

保留现有字段并新增一个低复杂度字符串字段：

```text
主线进度.当前阶段
主线进度.正史锚点.当前锚点
主线进度.当前节点          # 新增
主线进度.阶段状态
主线进度.已完成节点
主线进度.可触发节点
主线进度.正史锚点.玩家偏移
主线进度.下一步推进提示
```

示例：

```yaml
当前阶段: 阶段0·旧约·前日谭
当前锚点: 幻想御手篇
当前节点: FANTASY-HAND-03
阶段状态: 进行中
已完成节点:
  - FANTASY-HAND-01
  - FANTASY-HAND-02
可触发节点:
  - FANTASY-HAND-03
  - FANTASY-HAND-04
玩家偏移:
  - 玩家选择先保护佐天，改变了她接触Level Upper的顺序
```

### 5.2 字段职责

- `当前阶段`：大阶段，不承载过细剧情。
- `当前锚点`：当前事件包的正式名称，是换篇判断的主键。
- `当前节点`：事件包内正在推进的节点 ID，是本次改造的关键新增字段。
- `已完成节点`：只记录确实发生并完成的节点 ID。
- `可触发节点`：由当前节点和玩家行动开放的候选节点，不写不可达节点。
- `玩家偏移`：具体事实列表，不写抽象评价，不作为风险值使用。
- `偏移等级`：暂时保留以兼容旧聊天，但不作为剧情路由条件；后续另立清理任务。
- `下一步推进提示`：仅供模型维持节奏，不向玩家强制发任务。

### 5.3 状态更新规则

- 开局确认后初始化当前阶段、当前锚点、当前节点和第一批可触发节点。
- 当前节点发生变化时，用 `replace` 更新当前节点。
- 已完成节点和可触发节点发生变化时，优先替换完整数组，避免重复插入。
- 主线任务写入 `任务追踪`，支线任务也写入 `任务追踪`，但标明任务类型和所属事件包。
- 玩家改写事件结果时，同时写入 `玩家偏移` 和必要的 `世界线记录`。
- 旧聊天缺少当前节点时，不重写历史，不猜测性覆盖既有事实；下一次明确剧情行动时再完成一次状态校准。
- 当前锚点、当前节点、已完成节点必须相互一致，发现不一致时以最近实际发生的剧情为准，修正状态而不是重置整局。

## 6. 篇章软锁定和偏离规则

### 6.1 软锁定规则

当 `主线进度.正史锚点.当前锚点` 非空且 `阶段状态=进行中` 时：

- 当前事件包是本轮主线的唯一优先事件包。
- 允许日常、委托和人物互动穿插，但不能自动替换当前主线锚点。
- 后续篇章角色可以作为合理客串，但不能提前启动后续篇章的核心事件。
- 未完成当前核心节点时，不因模型生成困难、玩家短暂离场或一次支线互动而换篇。
- 每轮最多推进一个主要节点。

### 6.2 合法换篇条件

只有发生以下事实之一才允许更新当前锚点：

1. 当前事件包达到收束节点。
2. 玩家明确要求跳过或离开当前篇章。
3. 玩家明确选择新的时空锚点。
4. 玩家明确进行时间跳跃，并跨过当前篇章时间窗口。
5. 当前事件因玩家行动或世界线变化合理终止。

换篇时必须记录：

- 原篇章的状态：已完成 / 已跳过 / 已延后 / 已改写。
- 换篇原因。
- 玩家造成的关键偏移。
- 新篇章的首节点和可触发节点。

### 6.3 三类偏离

#### 篇章内偏离

玩家改变行动方式或角色关系，但事件主题仍存在。保留当前锚点，切换到事件包内部的分支节点。

#### 核心结果改写

玩家改变原著结局，但事件因果已经收束。保留当前锚点，将阶段状态设为“已改写”，写入具体世界线后果，再提供下一篇章或原创后续入口。

#### 明确离开篇章

玩家主动跳过、退出或进行时间跳跃。记录原因并关闭当前事件包，不强行把玩家拉回原著路线。

## 7. 世界书路由方案

### 7.1 目标路由

- `主线剧情导航`：蓝灯常驻，压缩为阶段目录、换篇规则和当前节点使用说明。
- 全局变量规则/输出格式/事件路由规则：蓝灯常驻，放在已经验证的指定深度 0 + system 位置。
- 详细事件包：改为绿灯 Conditional，使用正式篇章名、别名、事件核心词和关键角色作为关键词。
- 非当前篇章不应因其他篇章的角色客串而被完整激活；关键词需使用篇章专属主键，并通过次级关键词或运行时证据验证。
- 支线事件包：绿灯 Conditional，触发后作为任务或插曲，不能覆盖主线锚点。

### 7.2 激活可靠性试点

先只用幻想御手事件包验证以下两种候选路径：

A. 状态摘要/变量投影中出现当前锚点，通过递归扫描激活对应事件包。

B. 开局配置和每轮摘要中稳定输出当前篇章关键词，事件包使用关键词激活，并配合 sticky/合理扫描深度保持连续性。

必须在真实 SillyTavern 1.18.0 中验证：

- 当前篇章事件包实际进入模型上下文。
- 相邻篇章事件包没有同时进入。
- 当前关键词在下一轮仍然可见。
- 重载或多轮后不会静默失去当前事件包。

若 A 未通过，不继续依赖递归猜测；采用 B 或经 API 实测确认的等价路由。不得把未经实机验证的世界书递归行为当作已完成方案。

### 7.3 Token 和冲突控制

- 详细事件包不再全部 Constant，减少常驻 token 和跨篇章冲突。
- 每个条目只承担一个事件包的责任，导航、规则、事件事实和运行时状态投影分开。
- 全局常驻内容只保留必要的状态契约和阶段目录，不在常驻导航中重复全部事件流程。
- 事件包内部去除重复的通用世界观和角色介绍，角色详情继续由角色档案条目提供。

## 9. 验收矩阵

### 9.1 结构与契约

- [ ] 15 个原著事件包均有唯一 ID、文件、index.yaml 条目。
- [ ] 5 个既有支线统一事件包格式。
- [ ] 每个事件包节点数在 6-10 之间，节点 ID 唯一稳定。
- [ ] 每个包有核心事实、可改写部分、换篇条件、防剧透边界和状态写回契约。
- [ ] `当前节点` 在 schema、initvar、变量列表、更新规则、输出格式和示例中一致。
- [ ] 旧聊天缺字段时不清空、不重置、不覆盖历史状态。

### 9.2 世界书路由

- [ ] 主线导航和全局路由规则常驻。
- [ ] 详细事件包不再全部蓝灯常驻。
- [ ] 当前篇章激活时，当前包进入上下文。
- [ ] 非当前相邻篇章不会同时进入上下文。
- [ ] 关键词中文匹配、别名匹配和扫描深度经过真实运行时验证。
- [ ] 事件包不会因单个角色客串而误激活。
- [ ] 事件激活失败时有可诊断证据，不是静默假成功。

### 9.3 主线连续性

- [ ] 进入篇章后正确初始化当前阶段、当前锚点和当前节点。
- [ ] 正常推进每轮最多前进一个主要节点。
- [ ] 未完成当前篇章时不自动跳到后续篇章。
- [ ] 日常支线可以穿插但不覆盖主线锚点。
- [ ] 完成篇章后能进入合法的下一篇章或原创线。
- [ ] 页面重载、重新生成和多轮对话后状态保持。

### 9.4 玩家偏离

- [ ] 篇章内改变行动方式时仍留在当前事件包。
- [ ] 改写核心结果时记录具体 `玩家偏移` 和 `世界线记录`。
- [ ] 明确退出时记录“已跳过/已延后/已改写”等状态。
- [ ] 玩家主动选择新锚点时才发生跨篇切换。
- [ ] AI 不用“偏移等级”单独决定剧情跳转。
- [ ] 不出现强行拉回原著或无依据抛弃当前事件包。

- [ ] webpack production build 成功。
- [ ] schema.json 自动同步并与 schema.ts 一致。
- [ ] PNG chara 解码后包含全部事件包和路由规则。
- [ ] PNG 内无旧事件路径、旧 loader sha 或未声明文件。

## 10. 版本与止损策略

- 每完成一个可实机验收批次，建立一个可回滚 Git 提交。
- 首个试点只允许修改事件包、变量契约和必要路由配置，不顺手重构无关 UI 或脚本。
- 若路由试点连续两轮不能证明当前事件包稳定进入上下文，停止批量写作，重新检查实际 World Info 激活路径。
- 若模型/API 出现空回或截断，先用稳定 API/模型完成卡片验收，不把上游生成故障归因于事件包设计。
- 发布链固定为：源码修改 → webpack → push src → 等 bot bundle → loader sha 更新（仅脚本改动时）→ tavern_sync bundle → PNG tEXt 解码 → CDP 实机验收。
- 纯世界书文本修改不需要更新脚本 CDN sha，但必须重新打包 PNG。
