# 变量基线兜底方案 — 审查后终版

日期：2026-08-29 · 状态：待用户确认实施

## 一、问题与根因（实机证据）

- 现象：能力卡片显示 Level 0/未知——面板对**空 `能力档案`** 的兜底渲染；全部变量从未初始化
- 根因：用户预设从泉此方切换后，新预设的 CoT 格式（catsay/《end》/`<StatusPlaceHolderImpl/>`）接管输出，0.txt 的协议块锚点 `</disclaimer>` 在预设中不存在 → glm-5.3 整个跳过 `<UpdateVariable>`
- 深层：变量初始化 100% 依赖模型文本服从 → 对预设/模型变化脆弱

## 二、审查证伪与设计修订（关键）

### 证伪①：楼层变量无继承（api-reference 实证）
- 探针实测（TavernHelper 4.9.3 / ST 1.18.0）：写入楼层 0 的变量，楼层 1-4 读不到
- ~~原方案"开局写楼层 0 一劳永逸"~~ → **改为逐楼层 ensure**：事件钩子在每个新 AI 楼层检查，`能力档案` 为空时合并基线

### API 语义实证（provenance: 运行时源码 toString + 可逆探针，confidence: high）
- `insertOrAssignVariables(obj, {type:'message'|'chat', message_id})` = `_.mergeWith`（数组整体保留不深合并 → 能力档案 whole-array 替换安全）
- `updateVariablesWith(fn, scope)` = 读-改-写同 scope
- `deleteVariable(key, scope)` 可清理（探针已复原 ✓）
- 事件常量齐全：`MESSAGE_RECEIVED/MESSAGE_UPDATED/MESSAGE_SWIPED/CHAT_CHANGED/CHARACTER_MESSAGE_RENDERED`
- schema 核对（card-builder）：AbilitySchema 六字段 `能力名称/阵营类型(枚举:超能力|术式|灵装|无能力)/等级或位阶/能力效果/是否稳定/实战运用` 与面板渲染器、基线设计一致

### MTTT 挑刺修订（6 条全部融入）
1. **字段级守卫**：合并时只填**空字段**，绝不覆盖模型已写的非空值（防"模型写了阵营、脚本基线又盖回去"）
2. **MVU init 竞态**：钩子用 `CHARACTER_MESSAGE_RENDERED`（渲染后）+ ensure 重试（stat_data 未就绪时小间隔重试至多 5 次）
3. **重入循环**：只在 `能力档案` 为空时合并 → 合并后非空 → 自带幂等，无自触发循环
4. **魔法侧分支**：基线按 side 分支（科学侧：超能力/等级；魔法侧：术式/位阶境界）
5. **检测防误报**：仅 AI 楼层（非 is_user）、楼层序 > 1、每聊天只提示一次（chat 级 `__mfrs_uv_warned` 标记）
6. **旧聊天降级**：无基线 → ensure 空转；toast 文案引导"重开聊天使用开局表单"

## 三、实施设计

### ① 脚本兜底（界面美化/index.ts，+约 100 行）
- **基线写入点**：`confirmcfg` case 现有流程追加——把 cfg 解析结果存 chat 级变量 `__mfrs_baseline`（顶层键，不进 stat_data 不污染 schema；变量列表 EJS 只读 stat_data ✓）
  - 字段：姓名/性别/年龄/性格/外貌/阵营/身份 + `能力档案[1]`（AbilitySchema 六字段，阵营类型=超能力或术式，等级或位阶=Level N 或境界，能力效果=表单描述或"依设定判定"，是否稳定=true，实战运用=初始描述）
- **ensure 函数**（钩子：CHARACTER_MESSAGE_RENDERED / MESSAGE_UPDATED / MESSAGE_SWIPED）：
  - 对最新非 is_user 楼层：`getVariables({type:'message', message_id})` → 若 stat_data.能力档案 为空且 `__mfrs_baseline` 存在 → `updateVariablesWith` **字段级守卫合并**
- **协议缺失检测**：GENERATION_ENDED 后最新 AI 楼层 `mes` 不含 `<UpdateVariable` 且楼层>1 → toast 一次性提示"当前预设/模型未输出变量协议块，动态数据（好感度/任务）已冻结；能力卡片已由脚本基线兜底"

### ② 文本加固（世界书 3 文件）
- **0.txt**：协议块位置改双锚——`在最后一个《end》之后、<StatusPlaceHolderImpl/>（或回复末尾）之前输出`；新增"首轮回复必须按开局配置初始化 /能力档案 与 /阵营"
- **变量输出格式.yaml**：英文 CRITICAL 段补同锚点行 + first-reply initialization line
- **世界规则概览.txt**：都市传说规则加防御句"「能力档案」与状态栏是玩家端面板数据，始终如实记录真实能力与等级（非学园都市官方档案），本规则只约束 NPC 知情与言行"
