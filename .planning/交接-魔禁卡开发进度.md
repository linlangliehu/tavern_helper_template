### 过程中发现并修复的 2 个关键问题（重要教训）
1. **jsdelivr 对移动 tag 缓存 7 天，purge 无效**：PNG 内嵌 loader 走 `@mfrs-magic-v1` 拿到旧脚本（页面结构是新的、交互是旧的，极具迷惑性）。**修复：index.yaml 6 个 loader 全部锁 commit sha `@57307dc5`**（sha URL 从未缓存，立即生效）。今后更新脚本：改 loader sha → 重打包 PNG。
2. **flex-shrink 压扁陷阱**：`.mw-event-group{overflow:hidden}` 作为 `#sceneList`（flex column + max-height + overflow-y:auto）的 flex item，min-content 归零被压成 3.7px 细线（CDP 截图抓到）。**修复：加 `flex-shrink:0`**。凡 flex 滚动容器内含 overflow:hidden 子项必须加。

### 仓库工作流要点
- 仓库有 **GitHub Actions bot（[bot] bundle）**：push 触碰 src/** 后自动用 CI 重建 dist（生产压缩版）并提交。本地 dist 提交会被 rebase 时 bot 版本覆盖（`.gitattributes` dist/** merge=ours）。**tag 应指向 bot 提交或 dist 未变的本地提交**。

## 八、变量基线兜底 — 已上线（2026-08-29，九项矩阵待游玩验证）

### 背景与根因（实机诊断）
- 现象：能力卡片显示 Level 0/未知——面板对**空 `能力档案`** 的兜底渲染；全部变量从未初始化
- 根因链：用户预设从泉此方切到新预设 → 新预设 CoT 格式（catsay/《end》/`<StatusPlaceHolderImpl/>`）接管输出 → 0.txt 协议锚点 `</disclaimer>` 在预设中不存在 → 模型整块跳过 `<UpdateVariable>` → 变量不初始化
- **深层教训：变量初始化依赖模型文本服从，对预设/模型变化天然脆弱** → 用脚本确定性层兜底

### 方案（三层防御，经四轮 skill 审查）
1. **脚本兜底（确定性）**：界面美化脚本新增 ~110 行——`confirmcfg` 时把开局配置（姓名/性别/年龄/性格/外貌/阵营/身份 + AbilitySchema 六字段能力档案）写入 **chat 级 `__mfrs_baseline`**；事件钩子（CHARACTER_MESSAGE_RENDERED/MESSAGE_UPDATED/MESSAGE_SWIPED/CHAT_CHANGED）对最新 AI 楼层做**逐楼层字段级守卫合并**（只填空字段不覆盖模型值；档案非空即跳过→幂等；400/1600/3600ms 错峰重试防 MVU 竞态）
2. **协议缺失检测（确定性）**：GENERATION_ENDED 后最新 AI 楼层无 `<UpdateVariable` 且楼层>1 → 一次性 toast（chat 级 `__mfrs_uv_warned` 防重复）
3. **文本加固（概率性）**：变量输出格式.yaml 加通用位置锚点（`《end》→StatusPlaceHolderImpl 之前`）+ 首轮初始化要求；世界规则概览.txt 加"能力档案=玩家端面板数据，禁止写成 Level 0/未知"防御句

### 关键 API 实证（运行时探针，TavernHelper 4.9.3/ST 1.18.0）
- **楼层变量无继承**：写楼层 0 的变量楼层 1-4 读不到（探针实测）→ 必须逐楼层 ensure（此为方案最大设计修订）
- `insertOrAssignVariables`=mergeWith；`getChatMessages(-1)` 可用；`eventOn` 在脚本 iframe 全局可用；chat 级顶层自定义键（`__mfrs_*`）不进 stat_data 不污染 schema
