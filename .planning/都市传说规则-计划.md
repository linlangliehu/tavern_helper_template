# 玩家能力都市传说规则 — 计划

日期：2026-08-29 · 状态：待用户确认

## 一、目标

玩家开局选择的等级/能力在剧情中**不直接公开**：以"学园都市都市传说"形式存在，原著人物初始不知情，通过接触逐步了解。七人排名永不变动。

## 二、设计决策（用户已定）

1. **玩家能力/等级 = 都市传说**：开局无官方登记，原著人物不知道
2. **知情靠接触递进**：原著人物通过互动逐步了解
3. 七人排名永不变动（超编/无登记，不存在位次问题）

**红线（A0 门槛）**：①原著七人位次与剧情永不动；②变量结构不扩展（复用认知字段）；③脚本/CDN/loader 不碰。
## 三、方案设计（tavern-card-builder 契约）

### 3.1 信息载体：纯世界书文本，变量体系零改动

**关键发现**：`NPC关系.认知` 字段已存在，梯度"陌生/知道名字/知道身份/知道能力/知道阵营/知道秘密"与知情递进**天然匹配**——都市传说方案直接复用，不改 initvar、不改变量更新规则的结构（只加一行措辞锚定）。

- 写者：剧情模型（按认知梯度更新 认知 字段）
- 读者：变量摘要条目（已注入 stat_data）+ 关系折叠面板
- 无新增字段 → 无 schema/迁移/渲染改动

### 3.2 世界书改动（唯一源码改动点）

**文件**：`世界书/世界设定/世界规则概览.txt`
**条目配置**：不改（已存在：蓝灯常驻 + 指定深度0 + 系统角色 + 顺序14597，模型全程可见）
**新增段落**：第 2 条"超能力等级"之后插入 `== 玩家能力与都市传说规则 ==`，约 10 行：

```text
== 玩家能力与都市传说规则 ==
1. 适用范围：玩家开局等级为 Level 2 及以上时适用；Level 0-1 开局本规则不生效（无能力者本就不起眼）。玩家能力与等级不在学园都市官方档案中（测定数据异常/登记缺失，官方当作仪器故障或误差处理），坊间以"都市传说"形式流传，版本走样、真假掺半。
2. 七人排名永不变动：原著 Level 5 七人的位次与剧情不因玩家改变；玩家不属于排名序列。
3. 知情三层（推进时同步更新 NPC关系.认知 字段）：
   - 传说层（默认，认知=陌生）：NPC 只听过模糊传闻，不知真名真貌；玩家未出手前，NPC 不得虚构玩家的具体能力细节，传闻只许模糊走样。
   - 调查层（认知=知道名字/知道身份；"知道阵营"在本层后期获知）：暗部组织、Level 5 级人物、风纪委员可循线索调查，获知代号或外貌，真实能力仍不明。
   - 亲历层（认知=知道能力/知道秘密）：亲眼目睹、正面交手、或被精神系能力直接接触（如心理掌握读心）后，知晓真实能力与等级。
4. 单向性与例外：进入亲历层后永久知晓，不因时间流逝回退；除非剧情明确处理记忆消除（如心理掌握抹除在场者记忆），被消除记忆者按对应层重新归零。
5. 泄露机制：玩家当众使用能力→传闻自动升级（扭曲加重、波及扩大）；在原著大事件现场出手→相关势力进入调查层；玩家主动公开身份→相关 NPC 直接进入亲历层。
6. 写作要求：NPC 言行必须与 认知 字段一致——未达知情层者不得在言行中表现出知道玩家真实能力；已知情者言行应体现相应认知。科学侧按上述都市传说模板处理；魔神/圣人级开局不套用学园都市模板，改为"魔法侧势力隐约察觉异常波动、流传神秘存在的传闻"。
```

**变量更新规则.yaml**：在 NPC关系"认知"行追加半句锚定：
`认知体现该 NPC 对"玩家"了解多少……（初始一律为"陌生"，仅按都市传说规则第三条的知情三层推进）`

### 3.3 模型可见性账本（recipient ledger）

| 接收方 | 可见 | 影响 |
|---|---|---|
| 同代剧情模型 | ✅ 规则段（蓝灯常驻） | 按规则演出 |
| 变量更新模型 | ✅ 同一条目 + 变量更新规则锚定句 | 按 认知 字段落盘 |
| 两个模型都看 stat_data 的 NPC关系 | ✅ | 知情状态跨轮持久 |

## 四、不改清单

- 开场表单/欢迎页/index.ts（零改动）
- 超能力图鉴.txt（原著七人事实不动；不加玩家内容——AI 会从规则条目获得处理方式）
- initvar.yaml / 变量列表.txt / MVU（零改动）
- 脚本 / CDN / loader sha（零改动——纯世界书改动，无需更新脚本 sha）

## 五、实施步骤

1. 编辑 `世界书/世界设定/世界规则概览.txt` 插入规则段
2. `变量更新规则.yaml` NPC关系.认知 行追加锚定半句
3. `tavern_sync.mjs bundle` 重打包 PNG（世界书随卡走）
4. 提交推送（bot 可能静默——无 src 脚本变化，dist 不变）
5. 实机验收：导入 PNG → 新聊天 → CDP 确认 chara 世界书含新条目文本
6. （剧情行为验证交给用户实际跑 2-3 轮剧情观察 AI 遵循度）

## 六、风险与回退

- 规则条目变长约 400 字 → prompt 预算影响可忽略（蓝灯条目本就 3.6K）
- AI 遵循度风险：三层+泄露机制是明确可判定的规则，非模糊指导；若实测发现 AI 仍提前泄底，可在 系统提示词 世界书条目追加一句强调（后续迭代）
- 回退：删规则段 + 重新打包即可，无变量迁移负担

## 七、验证边界（诚实声明）

实机只能验证"条目注入成功"；AI 是否长期遵循知情三层需要用户实际游玩观察——这是所有规则类改动的固有验证边界。
