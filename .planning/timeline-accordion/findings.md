## 5. 实现策略：JS 动态分组（推荐）vs 静态HTML分组
- **JS动态分组**：读取现有 `.mw-scene` 卡片的 data-tag/data-date，按映射表分组注入 `#sceneList`。优点：不破坏现有HTML卡片结构，分组映射表可维护。缺点：需新增分组映射JS。
- **静态HTML分组**：手动把58个卡片重新排列进14个 `.mw-arc` 容器。优点：无JS依赖。缺点：改动巨大，HTML行数翻倍，易错。
- **决策**：采用 JS 动态分组，新增 `SCENE_ARCS` 映射表 + 分组渲染函数，原卡片HTML保持不变只是被JS重新包裹。

## 6. 风险与回退
- 风险：JS分组逻辑bug导致卡片丢失或顺序错乱
- 回退：保留原 `#sceneList` HTML 注释备份，或用 git 回退欢迎页.txt
- 校验：打包后PNG chara深度校验卡片数=58 + 14个 `.mw-arc` + 手风琴CSS/JS
