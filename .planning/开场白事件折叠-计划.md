## 三、运行时契约（第 5 轮 skill 审查：假设已源码级闭合）

原计划三处"需实机确认"的 DOMPurify 假设，已用目标运行时源码验证闭合（SillyTavern release 分支 `public/script.js:1898-1908` + `public/scripts/chats.js:1901-1938` 钩子源码 + dompurify@3.4.2 默认白名单；与本机 ST 1.18.0 实机观察一致）：

| 假设 | 结论 | 依据 |
|---|---|---|
| `<button type="button">` 存活 | ✅ 保留 | `button` 在 DOMPurify 默认 `ALLOWED_TAGS`；ST 无 USE_PROFILES/FORBID_TAGS 收窄 |
| `aria-expanded`/`role`/`tabindex`/`type` 保留 | ✅ 保留 | `ALLOW_ARIA_ATTR=true` 默认放行全部 `aria-*`；`role`/`tabindex`/`type` 均在默认 `ALLOWED_ATTR` |
| `data-act`/`data-event`/`data-tag` 保留 | ✅ 保留 | `ALLOW_DATA_ATTR=true` 默认；ST 未启用 `SAFE_FOR_TEMPLATES` |
| 键盘 Enter/Space 触发 click | ✅ 原生行为 | native button 天然支持，走既有捕获阶段委托，**无需 keydown 分支** |

其余已验证约束（记忆 #29/#30，实机验证）继续有效：onclick 被剥、class 前缀化 `custom-`（豁免 `fa-*`/`note-*`/`monospace`）、CSS 选择器加 `.mes_text ` 前缀、`:root` 失效须用 `#mfrs-welcome-root`、`<script>` 被 strip、运行时 JS 添加的 class 不被前缀化（脚本 class 操作必须手动带 `custom-` 前缀）。
**打包后实机验证降级为"顺带确认"**，不再是阻塞性未知项。

## 四、改动范围

### 4.1 welcome.txt（HTML 结构 + CSS）

**HTML**：在 `#sceneList` 内，把平铺的 60 个 `.mw-scene` 卡片，按事件分组包裹：

- 事件容器外层用一个 `<div class="mw-event-group">` 包住 `.mw-event`（标题栏）+ `.mw-event-body`（事件体），便于互斥时整组操作
- `.mw-event`（事件标题栏，**用真 `<button type="button">` 标签**而非 div+role——native button 自带隐式 role=button + Enter/Space 激活 + Tab 可聚焦，**不需要也不添加 `role="button"`/`tabindex="0"`**（冗余，第 5 轮审查修订）；只加 `data-act="event"`、`data-event="事件名"`、`aria-expanded="false"`）
- 标题栏显示：事件名 + 日期范围 + 开场白数量（如"禁书降临篇 · 7月19日—7月28日 · 5"）
- `.mw-event-body`（事件体，容纳该事件的若干 `.mw-scene` 卡片）
- **⚠️ 包裹边界**：事件分组包裹**仅覆盖 60 张 `.mw-scene` 卡片**（welcome.txt 约 479-718 行区间）；**自定义开场白按钮区**（720 行起 `<div style="margin-top:10px">` 含 #sceneCustomBtn + #sceneCustomBox）**留在所有事件组之外**，保持原位在 #sceneList 最底部。严禁把它包进任何事件组，否则折叠态会误隐藏它。
- 卡片本身 `.mw-scene` 结构不变，仍保留 `data-act="scene"` + `data-date`/`data-tag`/`data-desc`

**属性修改**：

- **补 data-tag**：22 张空标签卡片补上对应事件名（纯属性值修改，HTML 结构不变）
- **统一 data-tag**：把现有标签里不规范的统一（"大霸星祭"→"大霸星祭篇"、"妹妹们篇"→"妹妹们篇（克隆前史）"、"旧约开始"/"新约开始"/"第三次世界大战"归并等）
- **⚠️ data-tag 影响生成文本**：界面美化脚本 `index.ts:1280` 用 `【${date} · ${tag}】${desc}` 拼接开场白提交文本。统一 data-tag 后，玩家最终发送到对话的开场白标题里的事件名会同步变化（如"大霸星祭"→"大霸星祭篇"）。这是预期行为（标题随事件名规范化），非 bug，但需知晓。
- **修正描述**：按第八节核对记录修正 10/17、12/5 的 `data-desc`（及可能的 `data-tag`）

**CSS**（选择器一律写 `.custom-` 前缀，DOMPurify 自动前缀化已验证）：

- `.custom-mw-event`（标题栏样式，青蓝霓虹，复用 `.mw-navtab` 配色）
- `.custom-mw-event-body`（默认折叠态 `display:none`；`.custom-mw-event-group.custom-open .custom-mw-event-body` 展开态 `display:block`）
- 标题栏箭头/三角旋转动画（CSS `transform` 驱动，JS 只 toggle class）+ **`@media (prefers-reduced-motion: reduce)` 下禁用该过渡**（第 5 轮审查新增）
- **⚠️ button 样式重置**：`appearance:none; -webkit-appearance:none; background:transparent/继承; border:none; text-align:left; width:100%; cursor:pointer; color:inherit; font:inherit`，否则会带系统按钮外观破坏视觉
- **⚠️ 焦点可见性（第 5 轮审查新增，必做）**：button reset + 酒馆全局 `*{}` 规则可能吞掉键盘焦点环，必须补 `.custom-mw-event:focus-visible` 焦点样式（用 `var(--mw-accent)` 描边，如 `outline:2px solid var(--mw-accent); outline-offset:2px`）
- **⚠️ 窄容器换行（第 5 轮审查新增）**：标题栏 flex 布局加 `min-width:0`，"事件名·日期范围·数量"长 CJK 串在 ~320px 容器下需可换行（`flex-wrap` 或文本截断策略自定，验收见第七节）
- **⚠️ #sceneList 滚动布局**：现有 `.mw-scenes`（#sceneList）是 `max-height:420px; overflow-y:auto` 的**外层滚动容器**，包裹后**保留它作为唯一滚动层**；`.mw-event-body` 展开态只 `display:block`，**不单独设 overflow/高度**，由外层 #sceneList 统一滚动。避免滚动套滚动。事件标题栏不强求 sticky。
- **注意 DOMPurify 前缀化**：class 会变 `custom-mw-event`/`custom-mw-event-body`；CSS 选择器写 `.custom-mw-event`；JS 用 `custom-` 前缀操作 class（`custom-open`）或用 `data-event` 属性选择器

### 4.2 界面美化脚本 index.ts（交互逻辑）

在 `handleMfrsWelcomeDataAct` 里新增 `case 'event'`：

- 读取被点击事件栏的 `data-event`，找到其所属 `.custom-mw-event-group`
- **互斥 + toggle 逻辑（第 5 轮审查修订，核心变更）**：
  - 若当前点击的组**已带 `custom-open`** → 移除它的 `custom-open`（收起，允许全收起态）
  - 否则 → 移除所有组的 `custom-open`，给当前组加 `custom-open`（互斥展开）
  - 伪代码：`const wasOpen = group.classList.contains('custom-open'); qa('.custom-mw-event-group').forEach(g => g.classList.remove('custom-open','open')); if (!wasOpen) group.classList.add('custom-open','open');`
- 同步切换 `aria-expanded`：展开的事件栏 `aria-expanded=true`，其余全部 `false`（含收起操作）
- **展开后视口对齐（第 5 轮审查新增，建议）**：展开新事件后对其标题栏 `scrollIntoView({block:'nearest'})`，避免 #sceneList 滚动位置停在旧内容中段
- **⚠️ 不复用 mfrsWelcomeOnly**：`mfrsWelcomeOnly`（index.ts:1048）是单选互斥函数，操作的是 `custom-selected`/`selected`（选中态语义）。事件展开操作的是 `custom-open`（展开态语义），**语义不同，禁止复用**
- **折叠不清选中态**：`case 'event'` 只 toggle 容器显隐，**不操作 `.mw-scene` 的 `custom-selected`/`selected`**。折叠后已选开场白选中态保留，`root.dataset.scene` 不变，生成流程仍可用。折叠是纯视觉，不清空草稿状态
- 不阻止事件冒泡（不影响下方 scene 卡片的 capture 委托）

**折叠态选中可见性（必做，方案 a，第 5 轮审查升级）**：

- 事件标题栏支持 `data-has-selected` 属性，CSS 显示小圆点/数字徽章
- `case 'scene'` / `case 'scenecustom'` 选中/清除时，**全量重算 30 个组**（O(30) 便宜，不要只查当前组——否则跨组徽章残留）：对每个 `.custom-mw-event-group` 检查其内部是否有 `.custom-selected` 的 `.mw-scene`，有则给该组标题栏加 `data-has-selected`，无则移除
- 注：scenecustom 激活会清除 scene 选中（index.ts:1252 已确认能穿透折叠），徽章随之消失，行为一致

**可访问性**：

- native button 自带隐式 role=button + Tab 可聚焦 + Enter/Space 触发 click（源码级已闭合，见第三节），**无需 keydown 分支、无需 role/tabindex**
- `aria-expanded` 初始 `false` 静态写死，JS toggle 同步
- 执行时顺手确认现有 `data-act` 元素的可访问性基线，新事件栏与现状对齐
