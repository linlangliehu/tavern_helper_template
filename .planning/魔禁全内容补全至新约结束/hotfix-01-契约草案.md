# hotfix-01 契约草案：能力卡占位符修复

制定时间：2026-09-02 ｜ 状态：**草案 · 待用户批准**（批准前不改任何脚本）
性质：临时问题支线。独立契约、独立打包、独立验收、独立提交门（拆门原则见 task_plan「计划分层」）。

## 〇、缺陷与根因

用户实测发现：开局自定义能力未填描述时，能力卡长期显示占位符「依设定与剧情判定」。

三层失效链（已读源码确认，存量缺陷，非批次01引入）：

1. **时机一失效**：点「生成开局配置」时 `mfrsSynthAbilityByAi` 同步阻塞最多 25s 调 `generateRaw`（按钮禁用），失败/超时静默降级，占位符原样进基线。影响开局动线体验。
2. **时机二失效**：楼层守卫 `mfrsEnsureLatestFloorBaseline`（400/1600/3600ms 错峰）只在能力档案**整组为空**时写入；占位符非空 → 永不补全。
3. **时机三不可靠**：变量更新规则虽要求模型下轮 UpdateVariable 自觉 replace 占位符，脚本注释自证该路径不可靠，实测未发生。

## 一、修复方案（用户三轮决策 + 只读审查补强定稿）

### 时机一：去掉阻塞生成（保留提示）

- 删除提交侧 `generateRaw` 调用与 25s 等待：点「生成开局配置」立即出预览，开局动线零等待。
- 占位符照常进基线（不再有成功路径）。
- 仅保留零成本检查：`th?.generateRaw` 不存在（环境不支持）时非阻塞 toast「当前环境不支持 AI 生成，建议手填能力描述」，不卡任何人。

### 时机二：升级为主路径（楼层守卫补写）

- 挂既有楼层事件（CHARACTER_MESSAGE_RENDERED / MESSAGE_UPDATED / MESSAGE_SWIPED 等），错峰检查当层 `stat_data.能力档案`。
- 扫描占位/元文本：能力效果=「依设定与剧情判定」，实战运用=「随剧情展开；战斗与日常分别描述」，及「尚未展现/待补全/待揭示」系列。
- 命中 → 后台调 `generateRaw` 生成实质描述（30-60字效果+实战运用，沿用现有提示词约束：禁占位句/禁反噬措辞/玩家视角）→ 写回**当层** `stat_data`。只改能力卡片数据层，不碰回复正文。
- 幂等：已有实质内容绝不覆盖。
- 中期新觉醒能力若被模型写成占位符，同一守卫同样抓补。

### 护栏（审查补强，必须实现）

1. **in-flight 去重**：同一时刻只允许一个生成在跑；错峰重试不再 3s 内叠打（改为 800ms 首试 + 失败等下一次楼层事件再试）。
2. **每聊天上限 3 次**：`generateRaw` 连续失败 3 次即停手，能力卡显示引导文本提示手动补填；不空转重试。
3. **写回前二次校验**：写回前重读目标楼层 message_id + swipe 变体号，防止写进已滑走的变体。
4. **MVU 所有权边界**：只替换占位字段值，不整组 replace 能力档案、不覆盖模型/`mvu-protocol-applier` 已写的其他数据；不在 MVU 应用协议块的同一拍无条件写入。
5. **generateRaw 失败路径**：API 不存在或生成失败 → 停手 + 能力卡提示手填（非阻塞），不得假装"总会补上"。

### 时机三：只改措辞（世界书文本，搭车不改脚本逻辑）

- `世界书/变量/变量更新规则.yaml`：把「发现占位符下一轮必须 replace 补全」指令前移至【本篇能力与魔法结算】块第一条，措辞升级为"最高优先级补全任务"。
- 定位：锦上添花；保证仍靠时机二。

## 三、管线（脚本变更 → 完整 CDN 轮次）

```text
1. 改界面美化 index.ts + 变量更新规则.yaml
2. 本地 webpack 构建界面美化 dist（注意：构建会刷全部 dist，提交前按惯例 stash 噪音）
3. 静态门禁：YAML / 触发词不涉改 / 尺寸 / SHA 对比（仅授权文件变化）/ 安全扫描

5. 重锁 index.yaml 界面美化 loader 的 commit sha

7. 实机验收（用户导入新 PNG）：

   - 第一轮回复后能力卡从占位符变为实质描述（数据层变化，正文无痕迹）
   - 神之饮物篇触发/传闻行为回归正常
8. 验收通过 → 单独请求 hotfix-01 提交授权
```
