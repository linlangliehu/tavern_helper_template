## 背景

2026-09-03 实机游玩（琳琅档，皇帝特权 Level 5，幻想御手篇，15 楼）发现能力卡片从楼层 8 起变成「未知（待玩家填写）」。只读诊断（chrome-devtools 直读页面 context，全程零修改）定性：

- **AI 幻觉重置（主根因）**：楼层 8 UV 块含 `op:"replace" /能力档案` 整条 value=`[{能力名称:"未知（待玩家填写）", 等级或位阶:"Level 2（待玩家确认）", 能力效果:"依设定与剧情判定", 实战运用:"待剧情展开"}]`。applier 忠实应用（hash `0:1e325e78` 已标记），机制层零故障。「未知（待玩家填写）」等文案**不存在于**任何卡源码/dist/git 历史/预设/扩展设置——全酒馆运行时扫描仅楼层 8 swipe 数据命中，为模型凭空编造。
- **hotfix-01 守卫未救回（次因）**：占位扫描列表只有 6 种旧文案（依设定与剧情判定/随剧情展开/待补全/待揭示/尚未展现/随剧情展开；战斗与日常分别描述），未覆盖「待玩家填写/待玩家确认/待剧情展开」新变体；扫描范围只限 能力效果/实战运用 两字段，**能力名称/等级或位阶 污染无守卫**；修复时把污染后的能力名称喂给 generateRaw 合成器，产出错位内容（"风刃"——不贴皇帝特权）；chat 变量 `__mfrs_ability_fix_attempts=3/3` 已耗尽永久停手。
- **延续性**：楼层 10/14 UV 块被输出长度截断（`</UpdateVariable>` 未闭合）→ applier 跳过 → 楼层 12 完整但无能力档案操作 → 污染值随楼层快照复制到 14 楼至今。楼层 10-14 的 能力效果 被旧守卫合成值"生成微弱气流形成小型风刃"固化（错位内容）。
- **原始数据健在**：chat 层 `__mfrs_baseline.能力档案[0]` 与 chat 层 `stat_data.能力档案` 均保留皇帝特权完整条目（用户表单原文 + hotfix-01 修复后的实战运用），未丢失。

## 目标

1. **根治**：AI 凭空覆写 `/能力档案` 为占位文案后，卡内守卫确定性救回（不依赖模型自觉）
2. **恢复**：琳琅档「未知（待玩家填写）」自动恢复为「皇帝特权」（被 A 层吸收，无需单独数据操作）
3. **降概率**：协议层提示词禁止占位文案新变体与无意义覆写

## 改动范围（2 文件 + 运行时自愈）

### A. 守卫升级（`脚本/界面美化/index.ts`，核心修复）

**A1. 占位判定列表扩充**（`mfrsIsPlaceholderAbilityText`）——与 B 层黑名单为**同一张表**（见 B 层表格），两端逐字对齐防漂移：

- 既有 6 文案保留不变（依设定与剧情判定 / 随剧情展开；战斗与日常分别描述 / 随剧情展开 / 待补全 / 待揭示 / 尚未展现）
- 新增包含匹配 3 变体（本次实机捕获）：`待玩家填写`、`待玩家确认`、`待剧情展开`
- 【P1-1 修订】**"未知"判定范围收紧**：
  - `能力名称`/`等级或位阶` 两字段：允许"未知"类宽松判定（整值 `未知` / `未知（待玩家填写）`，及包含 `待玩家`/`待确认`）
  - `能力效果`/`实战运用` 两字段：**不做裸"未知"判定**（长文含"未知"二字的合法描述太多，如"对未知敌人"），仅适用上表黑名单
  - 判定函数按字段类型分两个入口：`mfrsIsPlaceholderIdentityText(value)`（名称/等级用，宽）/ `mfrsIsPlaceholderAbilityText(value)`（效果/运用用，维持收紧列表）

**A2. 扫描范围 2 字段 → 4 字段**

`mfrsFixAbilityPlaceholders` 内除既有 `effectStale`/`combatStale` 外，新增 `nameStale`（能力名称，用宽判定）与 `levelStale`（等级或位阶，用宽判定）。阵营类型不扫（枚举值，AI 写不出花）。触发条件：四者任一 stale。

**A3. 修复策略分叉（关键设计）**

```
if (nameStale || levelStale)            ← 身份字段被污染
   第一步（同步，不调 AI）：从 chat 层 __mfrs_baseline.能力档案[0] 回填
     身份三字段（能力名称/阵营类型/等级或位阶），仅替换仍为占位的字段；
   第二步（仅当效果/运用仍 stale）：用【回填后的干净名称】调 generateRaw 合成，
     入参 abilityName 取基线值（修复"风刃"错位根因——旧代码 ?? 链把污染名喂给合成器）
else if (仅 effectStale/combatStale)    ← 维持 hotfix-01 现状
   → AI 合成，abilityName 入参同样以基线名称优先（entry 名称次之）
```

【P1-2 修订】**名称+效果双占位时必须串行两步**：先基线回填名称 → 再用干净名称调 AI 合成效果。禁止并行/倒序（倒序则合成入参仍拿污染名）。

- **无基线时**（旧聊天未走开局表单，`__mfrs_baseline` 不存在）：名称占位且无基线 → **保守跳过 + toastr 提示手填**（不让 AI 编造玩家能力名）；效果/运用占位且无基线 → 维持旧逻辑（合成入参退用 entry 当前名称）。
- **MVU 所有权边界不变**：只替换"仍为占位"的字段，模型已写的实质内容永不覆盖。

**A4. 计数隔离重计**

- 新 key `__mfrs_ability_fix_v2_attempts`（上限 3），与旧 key `__mfrs_ability_fix_attempts` 完全隔离——所有聊天（含琳琅档）重新获得配额；旧 key 遗留值 3 不清理也不读，无干扰。
- 【P2 修订】**成功清零**：修复写回成功（`updateVariablesWith` resolve 且二次校验通过）后清零重计；失败才计数。旧语义"无论成败都计数"导致一次污染永久停手，废弃。
- 计数变更只发生在修复路径收尾（成功清零 / 失败 +1），不在中段写。

### B. 协议层加固（`世界书/变量/变量更新规则.yaml`）

能力档案 bullet 段（【本篇能力与魔法结算】块内）L14 最高优先级补全任务条扩充。**黑名单与 A1 同一张表**：

| 判定字段 | 黑名单文案 |
|---|---|
| 全字段通用（含效果/运用） | 依设定与剧情判定 / 随剧情展开 / 待补全 / 待揭示 / 尚未展现 / 待玩家填写 / 待玩家确认 / 待剧情展开 |
| 仅 能力名称/等级或位阶 | 未知 / 未知（待玩家填写） |

新增条款 1 条（【P2 修订】措辞与系统提示词 16 条对齐，避免规则冲突）：

```
- 「能力档案」六字段在开局初始化后即为玩家身份资产：后续轮次仅当①玩家剧情中明确获得/失去/变更能力，或②某字段仍为占位文案需补全时，才允许写 /能力档案；禁止把上一轮的合法值覆写为占位或"未知"类文本；不确定时保持原值不动。
```

同时把既有 L14 黑名单括号内的文案列举扩充上表新变体（待玩家填写/待玩家确认/待剧情展开）。

**注意**：schema 默认值（能力名称 '未觉醒'、等级 'Level 0'、效果 ''）**不列入黑名单**——'未觉醒'是合法初始态，守卫与提示词都不扫它。

**定位诚实**：B 层只降概率（楼层 8 当时信息完备仍幻觉，纯提示词已证不可靠——系统提示词 25 条"不得留空或写未知"本就存在且被违反）；确定性根治靠 A 层。

### C. 琳琅档恢复（被 A 层吸收，二选一）

- **C1. 自然自愈（默认路径）**：零操作。A 层部署后触发任意楼层事件（继续对话/切聊天回来/刷新页面任一渲染事件）→ 守卫扫末楼发现名称占位 → 从基线自动回填皇帝特权全条目 → toastr 确认。**注意**：升级卡后不对话直接看不会触发，需一次渲染事件。
- **C2. 立即手动回填（可选，需用户单独授权数据修改）**：chrome-devtools + `updateVariablesWith` 把基线能力档案整条 replace 到**仅末楼**（【P2 修订】历史楼层 8-13 不修——各楼 stat_data 独立，面板渲染与 EJS 注入都只看末楼，历史旧值不影响）。不等发版。

## 风险评估

- **A 层**：低风险。分叉策略（名称占位→基线回填，确定性；效果占位→AI 合成）比纯 AI 合成可靠；串行两步消除入参污染；无基线保守跳过防编造。唯一边缘：黑名单漏网新文案（P3 观察项承接）。
- **B 层**：低风险。条款与系统提示词 16 条（"运行期只能 replace 整个数组来增删能力"）措辞对齐不冲突；yaml bullet 已长（L14-17），新增 1 条控制在单行，条目体积远低于 14KB 红线。
- **C 层**：C1 零风险（无数据操作）；C2 属运行时数据修改，需用户单独授权，仅动末楼最小范围。
- **总体**：双层结构镜像 hotfix-06 已验收模式（防御层确定性 + 协议层降概率），管线为项目标准单 loader 轮次。
