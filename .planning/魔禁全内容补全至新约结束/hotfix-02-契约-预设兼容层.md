# hotfix-02 契约：预设兼容层（选项系统）· v3.1 修订版（守卫升级，已批准实施，附审查注记）

> v2→v3 修订（2026-09-02 实机验收结论）：
> ① 实测发现：兼容层条目已正确注入 prompt（深度0 pos15996、全文在位），但预设思维模板（STEP 流程 + 收尾惯例）在语义层接管输出结构定义权，AI 完成“正文→UV块→状态栏占位符”闭环后停笔，兼容层的“块缺失视为格式违规”输给预设 4 层近生成指令——**纯条目注入不足以保证生成**（Gate 1 验收标准 2 未达成）
> ② 对策：复用 hotfix-01 已验证的守卫模式（mfrsFixAbilityPlaceholders 同构）——脚本在楼层事件后检测无 choices 块时用 generateRaw 补生成并注入显示层（不写存储原文，避免污染楼层文本）
> ③ Gate 1 验收标准 2 修订：“连续 3 轮存储层出现 choices” → “连续 3 轮显示层出现 choices 按钮区（无论块来自 AI 原生输出还是守卫补生成）”
> ④ 新增 Gate 3（守卫层）：~60 行 / 1 文件，显式预算注记
## 目标

卡级预设兼容层：任何预设下，剧情选项**恒定生成 + 渲染为可点击按钮**，不依赖角色笔记、不依赖预设自己的选项渲染器。

### 兼容层条目全文（终审重点）

```text
【预设兼容层·选项输出契约】本条目是选项系统的唯一权威：规定 <choices> 块的内容与槽位。变量块的格式与落位以【变量输出格式】条目为准，本条不复述。

内容要求：
每轮回复必须输出恰好一个 <choices> 块，内含 3-5 个选项（A、B、C…编号），每个选项一句扮演者可立即执行的下一步行动（动作/对话/调查均可）。
- 选项必须贴合当前场景与扮演者已知信息；日常轮给日常向选项（闲聊/消费/探索），任务轮给任务向选项。
- 若本轮是纯过渡或无明确行动点的收束轮，也必须输出块，允许包含【继续推进】【稍作休整】类保底选项，保证块恒定存在。
- 选项只描述行动本身，不替扮演者决定情感与动机；不得引入数值判定、风险、失败收场机制（本卡无此类系统）。
- 选项文本不剧透未揭示剧情，不使用【变量输出格式】禁止的废弃路径或机制词汇。

槽位顺序（唯一合法位置）：
正文 </content> 结束 → <UpdateVariable> 块（按【变量输出格式】落位）→ <choices> 块 → 预设收尾标签（如 <StatusPlaceHolderImpl/>、</disclaimer>、《end》等）。
<choices> 块必须整体完整（<choices> 开、</choices> 闭），内部除选项行外不输出任何其他文本或标签。块缺失视为格式违规。
```

（实现注：文中【变量输出格式】以 index.yaml 该条目的真实注册名称为准。）

4. 门禁：YAML OK / 触发词 0 冲突 / 条目 ≤1KB / index.yaml 增量 ≤2KB

## Gate 3（守卫层）· 预算 ~80 行 / 1 文件 · 显式预算注记（v3.1 含缓存/截断增量）

### 改动文件

1. **修改** `脚本/界面美化/index.ts`（+约 80 行）：`mfrsFixMissingChoices` 守卫
   - 触发：挂在既有楼层事件链（同 mfrsEnsureChoiceUi），延迟 800ms（错峰，避免与 UV applier/按钮构建竞态）
   - 检测：最新 AI 楼层的显示容器内无 `.mfrs-choices`（即无原生块也无已渲染按钮）且非开局首楼
   - 补生成：`generateRaw`（复用 hotfix-01 模式）——系统提示=兼容层契约的选项生成部分，user 消息=最近楼层正文摘要+玩家信息，要求仅输出 `<choices>...</choices>`
   - 注入：把生成结果包进 `.mfrs-choices-src` 隐藏容器插入该楼层 `.mfrs-choices` 位（**不写回楼层存储文本**，applier 已定稿的原文不动），随后走既有按钮构建
   - 【v3.1 审查注记-P2a】补生成结果用 **message 级变量缓存**（键如 `_mfrs_choices_fix`，附楼层 id；只写消息变量，不动 stat_data、不写楼层文本）：显示层注入天然不持久，swipe/编辑/刷新后按钮区消失、守卫重触发会重调 generateRaw 再耗上限；有缓存则重渲染直接重建按钮——不重调、不耗额、不违反红线（消息变量 ≠ 楼层文本，hotfix-01 已有 message 级写先例）
   - 【v3.1 审查注记-P2b】行解析 `mfrsParseChoiceLines` 每行加长度上限（如 100 字符截断），防异常生成撑爆版面（对齐 hotfix-01 的 `.slice(0, 200)` 先例）
   - 【v3.1 审查注记-P3】守卫注入容器**不带 `data-mfrs-built`**，注入完成后**手动调用** `mfrsEnsureChoiceUi()` 完成按钮构建（守卫在渲染事件之后异步完成，事件链不会替它跑构建）
   - 护栏（对齐 hotfix-01 五护栏）：in-flight 去重 / 连续失败 3 次停手（【v3.1 用户拍板读法 B】chat 变量计数，只有生成失败 +1，成功重置；AI 原生输出与守卫成功均不消耗额度）/ 写入前二次校验（楼层 id 重读，防 swipe 错位）/ 失败静默停手（不弹错误 toast，选项系统是增强非必需）/ 已有按钮立即返回幂等
   - 若 generateRaw 不可用：静默跳过（选项系统退化为“AI 偶尔输出才显示”，与现状等价，无害）

### Gate 3 验收标准（按序）

1. 人间月下实测：连续 3 轮显示层出现 choices 按钮区（原生或守卫补生成均计入）
2. 存储层原文零污染：守卫补生成后楼层存储文本不含补生成内容（【v3.1】连接器读存储文本为客观证据）
2a. 【v3.1】缓存命中路径：swipe/编辑/刷新页面后按钮区由 message 级缓存重建，不重调 generateRaw、不消耗 3 次上限（读 chat 变量计数不变为证）
2b. 【v3.1】超长选项行截断生效（构造 >100 字符选项行，版面不撑爆）
3. 连续失败 3 次停手生效（【v3.1 用户拍板读法 B】构造 3 次连续失败——如临时断网/端点故障——后第 4 轮无补生成尝试，console 无报错；生成成功或 AI 原生输出均重置/不消耗额度）
4. swipe/编辑/重渲染幂等：无重复按钮区、无重复计数消耗
5. 开局首楼（sp_start 开局页）不触发守卫
6. tsc 零新增错误 / 安全扫描 0 内联事件 0 远程引用
