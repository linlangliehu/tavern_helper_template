## 二、P1 修复内容

### 根因（已确认，非 HANDOFF 原假设）

`vendor/shujuku-sp-fork/index.js` 的 `NativeTableServiceAdapter.loadFromChat` 只委托 `loadOrCreateJsonTableFromChatHistory_ACU`：
模板预置行被 `parseTableTemplateJson_ACU({stripSeedRows:true})` 剥成 header-only + `table.seedRows` 字段挂载，**content 不含预置行**。
前端 `updateCell match row_id 1..N` 在空 content 里 `ROW_NOT_FOUND`，镜像/vendored CRUD 的后置 `insertRow` 自愈只是补救，不是根治。
现有 `materializeSeedRowsIfNeeded_ACU` 只在 `parseAndApplyTableEdits` 的 `<tableEdit>` insert/update/delete 路径局部生效，**覆盖不了前端 updateCell**。

SQLite 路径有自己的 `_ensureTablesFromTemplate` 消费 seedRows，正确；**不复用、不复制**到 native。

### 修复位置

在 **vendor native provider 加载层**（`NativeTableServiceAdapter.loadFromChat`）补种，**不**改前端 adapter / CoreMirror / mvu-core-mirror。

### 关键设计（务必沿用）

1. **每表「未持久化」运行时标记**（非枚举 Symbol，例 `NATIVE_UNPERSISTED_GUIDE_SHEETS_MARKER_ACU`），值=本次 **merge guide 中无历史快照** 的 sheetKey 数组。
2. `mergeAllIndependentTables_ACU` 在最终 reorder/clone**之后**、return **之前**挂 marker；否则 JSON clone 会丢 Symbol。
   - 全新 `source=initialized` → 物化所有有 seedRows 的固定表。
   - 部分历史 `foundCount>0` → 只标记本次缺历史表，仅补种缺的（支持「global 已落盘、check 缺失」式分轮持久化）。
3. **绝不**仅用全局 `content.length===1` / header-only 判断：那会把用户主动清空的旧聊天复活。
4. 物化条件 `content.length===1`，深拷贝 seedRows 追加，**已有行不覆盖、重复加载不重复插入**。
5. **只改内存**，不立即 `saveChat`/persist/notify，避免递归保存与 enqueue 竞态；`loadFromChat` 是串行完成点，前端看到的就是完整行。
6. SQLite provider **不**接入该 helper（路径隔离已验证）。

### 受影响预置行（模板 `src/神秘复苏模拟器/数据库/神秘复苏表格SQL_v1.json`）

| 表 | 行数 | row_id |

| 全局状态 | 1 | 1 |
| 玩家状态 | 1 | 1 |
| 行动建议 | 4 | 1..4 |
| 检定建议 | 5 | 1..5 |

合计 11 行；其余 10 表种子为 0。
**注意**：检定建议首轮 updateCell 来自 vendor CRUD Plan/fallback（`index.js:37340-37364`），**不是** `mvu-core-mirror.ts`；所以必须在 provider load 层统一覆盖所有来源。

新增 `scripts/verify-mfrs-native-seed-rows.mjs`（行为门禁，仿 `verify-mfrs-sqlite-cold-start.mjs` 的真实 vendor class/function slicing + vm mock），用例：

## 四、给下一位的关键经验

**❗ 别让 API 网关故障卡死整个流程。** 本会话多次 401/503/429（希希公益站线路），子代理一断就重派。验证这种纯静态/Node 脚本子代理**不需要高档模型**，可降到 sonnet 甚至直接主代理自己跑门禁——只验证不写代码不会拖慢。

**❗ mutation proof 是独立验证的核心。** 门禁 PASS 不代表接线正确。必须临时破坏两种条件（物化逻辑、marker 接线）确认 gate 都会失败，否则只是「我写了它就过」。

**严格保护在途改动。** 本次 P1 三个目标文件与四份无关在途改动**物理共存**于工作区。提交时只能精确 `git add` 三个文件。历史多次因 `git add -A` 误把开发卡/localhost/HUD 改动混进发布提交。

**真页验收三件套**（每次都要查）：
1. 当前是哪张卡（开发卡指向 localhost 还是发布卡指向 CDN）
2. 服务器 dist 是不是新的（`fetch(url + '?bust=')` 校验特征字符串）
3. 代码是否真的挂上了（`String(api.insertRow).includes('chronicle-audit')` 式检查，别假设写了就生效）

**CDN 传播滞后是正常的。** 固定 ref 的新 dist raw 可能还拿不到最新压缩串，以 GitHub raw + 静态门禁为远端证据，不要把「CDN 还没传播」当成修复没生效。
