> 内容边界：旧约、新约 1–22 卷与 22 Reverse，以及已立项外传；创约仅用于排除误归属，不自动纳入卡内。
> 结论：旧方案确有实施记录，但不能称为“全系列逐事件核验完成”。本表覆盖当前 27 个主线事件包及主要缺口；没有读到小说全文、全部漫画各话或原图每个小格。

## 1. 如何使用与裁决

- 六列分别保留事件身份、**原图原样读数**、卷／话定位、实际联网出处、当前源码状态、待实施裁决；不能用最后一列反写成“原图本来如此”。
- `图推`：2026.jpg 的社区排期，可能含原文日期、推算或整合安排；本轮未取得逐格原始推导，不能统一标成“原作明示”。
- `官动`：[S01 官方动画年表][chronicle]，可证明动画剧情日期／集数；不自动证明小说每一章采用相同日历。
- `官介`：电击文库官方卷页正文／书介，可证明该卷涉及的情节；只有书介明写的故事日期才可引用为日期证据，**出版日期不算剧情日期**。
- `社文`：实际读到正文的社区条目；可辅助卷区间与篇章归属，精确日仍须另证。`待核`不是“已证实无此事件”。
- 裁决顺序：同一媒介的原作明示（本轮尚无章页取证）→对应官方资料→可复核社区归纳→项目设计。跨媒介有冲突时并列，不以“网页更新较新”或“图更整齐”为裁决理由。
- **事件主体、前奏、后日谈、欢迎页精选入口、回忆发生时点**分开登记。玩家可改写剧情；改写线不能回填为原著事实。
- 表内 `W:行号` 指[欢迎页][welcome]的本轮源码快照，`包 ID` 指对应主线文件；行号会随修改移动，后续以分组标题和事件包 ID 定位。`无独立包`不等于没有任何提及，也不等于合并包已完整覆盖。
