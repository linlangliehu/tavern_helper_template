- 回忆发生日、当前叙事日、并行视角和跨作品改编分支必须分开记录。

## 二、P1 导航结构裁决

### 2.1 不再使用严格的单一路径

当前的“时间线 → 事件 → 开场白”结构默认每个事件都有唯一日期、唯一作品版本和唯一现场。在魔禁、超炮和一方通行的重叠剧情中，这个前提不成立。因此 P1 实施阶段不再把精确日期作为唯一父级排序依据。

推荐结构为：

```text
叙事时间层 / 故事阶段
└─ 作品线或剧情事件簇
   └─ 视角、媒介或剧情阶段分支
      └─ 开场白入口
```

例如：

```text
Y 当前学年·夏季
└─ 8月31日并行事件簇
   ├─ 最后之作视角
   ├─ 一方通行视角
   ├─ 艾扎力/海原光贵视角
   └─ 闇咲逢魔视角
```

大霸星祭则应保持一个共同事件簇，下挂祭典日常、超炮科学侧、使徒十字魔法侧和角色个人行动，而不是把所有内容压成 9 月 25 日的闭幕事件。

### 2.2 三层导航的职责

| 层级 | 作用 | 不承担的职责 |
|---|---|---|
| 叙事时间层 | 表示前史、当前学年春夏秋冬、创约阶段、回忆层或外传分支 | 不宣称该层内每个事件都有精确日 |
| 事件簇 | 聚合共享背景、时间窗口或因果关系的事件 | 不把不同现场、不同作品或不同媒介强行合并 |
| 分支入口 | 表示角色视角、媒介版本、前奏/主体/余波和具体开场 | 不把一个开场白冒充成整卷剧情的唯一入口 |

因此建议将界面上“时间线”理解为“故事阶段导航”，精确日期改为事件或入口的辅助标签、筛选条件和排序信息。

### 2.3 事件/入口元数据建议

第一批 P1 卡内实施已按现有 `data-meta`/`data-compat` 契约补齐以下字段；字段语义仍以事件簇矩阵和维护源为准：

| 元数据 | 建议值 | 用途 |
|---|---|---|
| `timeLayer` | `Y-1`、`Y-spring`、`Y-summer`、`Y-autumn`、`Y-winter`、`Y+1`、`memory` | 稳定的故事阶段归属 |
| `clusterId` | 如 `CL-0831`、`CL-DAIHASEISAI` | 共享背景或并行关系的事件簇 |
| `media` | `novel`、`manga`、`anime`、`game`、`movie`、`mixed` | 区分媒介版本 |
| `viewpoint` | `kamijo`、`misaka`、`accelerator`、`ensemble` 等 | 区分同一窗口内的角色视角 |
| `datePrecision` | `exact-day`、`official-range`、`relative-time`、`media-window`、`project-window`、`unknown` | 防止近似日期被显示为原作事实 |
| `entryType` | `prelude`、`main`、`aftermath`、`memory`、`reference` | 区分前奏、主体、余波、回忆和索引 |
| `relation` | `parallel`、`precedes`、`follows`、`recall-of`、`media-variant` | 表达事件关系而非强行排成单线 |
| `coverage` | `full-playable`、`partial`、`reference-only`、`project-window`、`pending` | 表示当前卡内实现程度 |

建议保留现有 `Opening ID`，以元数据补充和重新分组为主，不因为导航重构而无理由重命名全部入口。

### 2.4 必须支持的重叠场景

- **8月31日并行事件簇**：最后之作、一方通行、艾扎力/海原和闇咲逢魔共享时间段，但保持独立视角和独立收束。
- **大霸星祭并行事件簇**：祭典整体、超炮科学侧、使徒十字和校园日常共享 9/19–9/25 背景，但不能互换目标、角色或结局。
- **回忆事件**：新约11当前框架可位于 11 月下旬，而上蜂往事位于前一年夏天；美琴一年级、才人工房和生物黑客也应与当前触发日期分开。

### 2.5 方案收益与代价

优点：不需要为了形成线性菜单而制造未经证实的精确日期；可以容纳同日并行事件；可以明确区分不同作品和媒介；可以把前奏、主体、余波和回忆分开；可以保留现有入口 ID，通过补元数据和调整父级分组渐进迁移。

代价：菜单不再是一条严格的逐日历，需要维护事件簇、媒介、视角、日期精度和事件阶段等额外元数据。

建议采用“主导航按叙事时间层/事件簇，辅助筛选按日期/作品/媒介/精度”的折中方案。
